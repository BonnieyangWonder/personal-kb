# Add Requirement Dependency

快速补充 [[个人/需求关联清单.md]] 中的新需求关联。这是 Bonnie 的个人 RA 辅助工具，用于在需求分析前避免遗漏隐含关联。

## 何时使用

当你在进行需求分析或深入了解一个功能时，如果发现有新的需求关联、隐含需求或容易被遗漏的影响点，使用本skill快速记录。

**触发场景**：
- 进行 Cookbook 需求分析时，发现某个需求涉及多个系统交互
- 分析某个功能时，意识到需要检查的关联项
- RA 完成后，总结出可复用的关联关系，供后续参考

**自然语言触发**（识别意图，不需要精确措辞）：

**中文**：
- "补充需求关联"
- "发现了一个需求关联"
- "有个新的关联需求"
- "需求关联补充"
- "加一个关联到清单里"
- "记录一个需求关联"
- "这个需求还有关联..."
- "补充关联需求"
- 直接说出需求信息：「XX 除了 YY，还要考虑 ZZ」

**English**：
- "add a requirement dependency"
- "record a new association"
- "capture this requirement relationship"
- "log a dependency"

输入形式无特殊要求——可以是完整表述，也可以只是关键信息，我会根据 skill 规范帮你整理补充。

## 执行步骤

### Step 0 — 收集信息

整理以下信息（不需要全部提供，但越完整越好）：

1. **需求类别**：主要功能模块分类（如 Cost, Item Lifecycle, Menu Management 等）
2. **主需求**：当前聚焦的核心需求或功能点
3. **相关系统/模块**：涉及的其他系统或内部模块
4. **隐含需求**：容易被遗漏的关联需求或隐含影响
5. **检查清单**：RA 时需要验证的具体问题或决策点

### Step 1 — 编辑清单

打开 [[个人/需求关联清单.md]] 并按以下规则添加新行：

**表格行格式示例**：

```
| **[需求类别]** | [主需求名称] | [相关系统1] + [相关系统2] | 1. [隐含需求1]<br>2. [隐含需求2]<br>3. [隐含需求3] | - [ ] [检查项1]<br>- [ ] [检查项2]<br>- [ ] [检查项3] |
```

**填充指南**：
- **需求类别**列使用加粗格式 `**XX**`，便于快速扫描
- **隐含需求**和**检查清单**如果有多项，用 `<br>` 或换行符分隔，用序号或符号编号
- 检查清单中，容易遗漏的项用 `- [ ]` 标记（Obsidian task format）
- 保持表格对齐，确保 Markdown 表格正确渲染

### Step 2 — 验证与反思

添加前，问自己：

1. 这个关联是否确实容易在 RA 时被遗漏？
2. 隐含需求的描述是否足够清晰，让 6 个月后的自己也能理解？
3. 检查清单是否足够具体，能直接用于下一次 RA？

### Step 3 — 更新清单

1. 添加新的表格行
2. 更新 frontmatter 中的 `updated` 字段为当前日期
3. 保存文件

## 例子

**场景**：分析 Item Cost 需求时发现的关联

**收集信息**：
- 类别：Cost 管理
- 主需求：Item Cost 字段
- 相关系统：Cookbook, ERP
- 隐含需求：Cost 同步逻辑、数据一致性校验、双向修改处理
- 检查点：映射规则、回写机制、一致性保证

**添加到清单**：在表格末尾追加新行（已在清单中）

## 最佳实践

1. **及时记录**：在 RA 过程中发现关联时立即补充，不要等到完成后才记录
2. **避免重复**：添加前检查是否已有类似记录，可以合并或补充细节
3. **聚焦隐含需求**：记录的应该是不明显、容易被遗漏的项，而不是显而易见的主功能
4. **参考化**：写得足够清晰，让其他人（或未来的自己）也能理解和复用
5. **定期回顾**：月底或季度末回顾清单，总结规律和经验教训
