## Background

Charlie Fox requested two new validations for Intelligent Kitchen (IK) line builds to reduce CE team configuration errors.

Discussed in detail between Bonnie Yang and Charlie Fox in Slack, with the following conclusions: [link](https://remarkable-foods.slack.com/archives/C06FJQA9RFD/p1781704183925619?thread_ts=1781641346.616259&cid=C06FJQA9RFD)

- **Validation 1**: WARNING level — because users can independently remove the "Machine Eligible" attribute from components after save, an error would not be reliable. Warning is sufficient.
- **Validation 2**: ERROR level — IK Eligible steps that are separated or come after regular steps will cause unexpected behavior in the KDS.

The way the IK super pods will be set up is there will be a new IK pod (representing the machine) followed by a hybrid pod (representing what Spyce calls the "finishing station"). All of the IK-eligible steps will be assigned to the IK Pods, and everything else will be assigned to the hybrid pod. In all cases items must flow from the machine to the finishing station, which is why all IK-eligible steps must come first. Any instruction needed at the finishing station should be listed as non IK-eligible so that they are assigned to they hybrid pod and are displayed after the chef removes the bowl from the machine. Hence, this is the right place to put a garnish instruction that specifies the final packaging type the contents of a metal bowl from the machine should be transferred to.

### Validation 2 — IK Eligible Step Ordering Constraint (ERROR)

**Context:**

- IK items must start at the machine and cannot leave and be handed back — hence IK steps must be grouped at the start.
- They only need to add a step like this when the "IK Dish Type" is "Metal Bowl", because the contents of the bowl will be put into different packaging. Even then, the packaging instruction (like "28 oz Pulp Rectangle") will be moved below the block of "IK Eligible" steps

**Requirement:**

1. When saving a line build that contains any "IK Eligible=true" step:
   2. All IK Eligible steps must appear **first** in a task in the line build (before any non-IK steps)
   3. All IK Eligible steps must be **consecutive** in a task (no non-IK steps between them)
   4. Steps without mapped components or customization options (instruction-only steps) are **disallowed** before or between IK Eligible steps
   5. This is an **ERROR** validation — it blocks saving the line build.
   6. Error message:
      1. Unable to save line build: IK Eligible steps must come first and be consecutive, please move the below IK Eligible steps to the top of task(s).
      - Task ({task name})-Step1, Step4, Step5.
      - Task ({task name})-Step1, Step3
